# 「今天吃什么」V2.0 Benchmark Review

## 1. 文档目的

本评审服务于 V2.0 产品规划，目标是从三个公开项目中提取适合「今天吃什么」的产品表达、版本管理和 AI 协作机制。它不是功能竞品分析，也不以仓库 Star、视觉完成度或作者自述代替实际证据。

- 评审日期：2026-08-26
- 当前基线：已公开部署的 V1.0 Portfolio MVP
- 研究对象：三个指定公开 GitHub 仓库的 README、目录结构及其中公开的工作流、PRD、Prototype 与 Flowchart 文档
- 证据边界：仓库自述只证明“文档如何表达”，不证明真实用户效果、商业结果或线上功能完整性
- 采用原则：解决当前项目的实际问题、保持增量、可以验证、不会破坏现有测试与部署基线

## 2. 当前项目基线

「今天吃什么」已经具备从 Idea 到公开部署的完整过程资产：PRD、UX Design、Prototype Spec、24 Frame 可点击原型、生产 Demo、自动化测试、README 与 GitHub Pages CI/CD。当前缺口不是“再做一套完整流程”，而是：

1. 把 V1.0 的真实结果沉淀为可审计复盘；
2. 用增量文档管理 V2.0，而不是覆盖 V1.0 事实；
3. 让研究、版本计划和通用工作流有稳定入口；
4. 区分产品假设、文档事实、自动化验证和真实用户证据；
5. 避免指标、竞品评分和效果结论出现无来源数字。

## 4. 分项目评审

### 4.1 我的技能分你一半

该仓库最有价值的部分是 README 的“单页产品叙事”：先说明市场问题和双边角色，再给出交易主流程、异常、状态机、集合结构、漏斗与未来版本。它证明复杂业务可以被招聘者或协作者快速扫读。

适合本项目的迁移方式是缩短阅读路径，而不是照搬内容结构：

- 在 V2.0 计划开头给出问题、规则变化和用户价值；
- 用一张数据变化表说明 `expiresOn/useSoon` 到 `purchasedOn` 的迁移；
- 把推荐链路与指标口径写成可验证规则；
- README 只提供摘要与链接，详细事实仍留在版本文档。

不适合直接采用的部分：

- 产品、技术栈、供应商和部署密钥准备混在同一 PRD 叙事中；
- 仓库公开树只有 README，无法用代码、测试或 workflow 交叉验证；
- 交易、实名、支付、LBS 等复杂度与本项目增量无关。

### 4.2 PM Flow

PM Flow 的核心价值不是 HTML 模板，而是把模糊想法转化为阶段化交付，并在需求、差异化、原型和最终交付前设置确认点。其文件结构也把工作流主体、参考规范、模板和资产分开，降低单文件负担。

本项目采用以下机制：

- 自适应追问：只询问会改变产品架构或范围的问题；
- 证据化 Benchmark：每个启发必须回答是否适用、如何采用、为何不采用；
- Human Decision Gate：方向、范围、数据语义和公开外部操作由人决定；
- Version Management：保留历史事实，新增增量计划和复盘；
- 交付检查：每阶段有输入、输出、验收与停止条件。

本项目明确不采用：

- 强制所有项目走同一八步深度；
- 高保真单文件 HTML 作为默认产品文档；
- 通过 iframe 把 PRD 与 Prototype 强绑定；
- 为每个小版本复制整套历史文件；
- 没有来源时补全市场规模、评分、用户原话或目标值。

### 4.3 骑乐星球

骑乐星球展示了版本化 PRD、两代 Prototype、Flowchart 和在线预览如何组合成 Portfolio。v0.5 主动标注“待原型确认”的章节，是值得保留的证据边界；README 对核心玩法、指标和文档入口的压缩也适合外部展示。

对本项目最直接的启发是：

- 让 V1.0 复盘、V2.0 计划和通用工作流成为可发现的 Portfolio 资产；
- 用 P0/P1/P2 管理增量，而不是重新打开 V1.0 Scope；
- 把指标分类，但不把假设目标包装成实绩；
- 发布前核对 README、实际树和在线链接。

不采用完整 HTML 版本复制。公开树显示 README 的目录描述与实际文件存在轻微差异，例如实际保留了两版 Prototype，而 README 只列最新版；README 还列出公开树中未出现的 research 目录。这说明“物理版本隔离”若缺少同步门禁，也会制造文档漂移。

## 5. 最终采用决策

### 5.1 本轮采用

1. `docs/research`、`docs/iterations`、`docs/workflow` 三层文档结构；
2. 版本计划与版本复盘配对；
3. Evidence 明确区分产品事实、原型/自动化证据、用户输入和未验证假设；
4. P0/P1/P2 增量优先级；
5. Human Decision Gate、Scope Freeze、Test Gate、Stop Conditions 与 Change Propagation；
6. README 在 V2.0 实施完成后增加过程文档入口；
7. 指标定义与实际数据分离。

### 5.2 本轮不采用

1. 搬迁或复制根目录 `PRD.md`、`design-document.md`、`prototype-spec.md`；
2. 创建 HTML PRD、iframe 原型切片或新的 Flowchart；
3. 重写现有 Prototype；
4. 引入工作流 Skill、Tailwind、框架或第三方服务；
5. 无来源竞品打分、市场规模估算、用户引语、基线或目标值；
6. 把登录、AI、地图、外出场景等 Roadmap 项目提前纳入 V2.0。

## 6. 仓库结构建议

本轮采用以下增量结构，现有事实源保留原位：

```text
docs/
├── research/
│   └── benchmark-review.md
├── iterations/
│   ├── v1.0-retrospective.md
│   └── v2.0-plan.md
└── workflow/
    └── ai-product-development-workflow.md
```

未来若要移动根目录产品文档，应单独规划链接迁移、README 更新、GitHub 历史可读性和发布检查；不在 V2.0 规划阶段执行。

## 7. 研究限制

- 本次研究对象由用户指定，样本数量小，且并非同品类产品；结论只用于产品过程与 Portfolio 表达。
- 未进行这些项目的用户访谈、真实数据核验或维护者访谈。
- 公开仓库的 README 与代码树只能证明公开内容，不证明商业指标或未公开实现。
- GitHub 网页索引对两个仓库出现缓存缺失，目录与文件内容已通过 GitHub 公开只读 API 交叉核对。
